| Codex | [SessionStart](https://learn.chatgpt.com/docs/hooks) supports context output. The fetched hook reference does not establish an environment-export channel | Private record discovery still needs evidence that the calling command and delivery hook belong to the exact registered thread, especially when threads share one process |

Codex's hook reference states that subagent hooks carry the parent's `session_id`. Ordinary `PostToolUse` fields do not include `agent_id`; the transcript format is explicitly unstable. A process ancestry check cannot by itself distinguish threads in the same process. Native identifiers may locate a private record, but neither an inherited identifier nor an arbitrary transcript path is authentication. These are unresolved production binding questions, not a claim that every possible integration is unsupported.

An owned non-hook `codex exec --json` test confirmed the shared-process case at 08:10 to 08:11 UTC. Its root shell received `CODEX_THREAD_ID=01a09ef7-fbdb-7391-8154-f2ba97601ac9`; its single native child received `01a09ef8-25fc-77b1-8f20-39fc5d16f811`. The command PIDs were 2174177 and 2174427, both direct children of Codex PID 2173536, with process start counter 79385708 and boot ID `3cb043eb-f7b1-4588-af7d-c3fe9c530c07`. The observed environment distinguished those native threads; kernel ancestry did not. Both commands and the owned client exited zero. The native PID was absent after exit. This was an identity feasibility test, not a LAM exchange or credential proof. No transcript inspection or environment dump was needed. [The focused artifact](chat-probes/2026-09-14/task-6-binding/README.md) retains exact records and invocation.

The same Codex reference documents a default approximate 2,500-token threshold that replaces larger hook output with a saved-file preview. `additionalContextLimit` can change that threshold. Installed-version support and full inline exposure of the bounded Rust payload still need proof before enabling delivery. The initial checkpoint changed no native configuration.

A later explicitly approved diagnostic probe ran at 12:21 to 12:22 UTC through the exact temporary project hooks and ordinary native trust review. The frontend was 0.154.0 but the executing shared server was 0.153.4, PID 28534; these are not standalone 0.154.0 hook results. This supplies positive hook-discrimination evidence without choosing a participant restriction. Private credential issuance and actual authenticated commands still need proof. [The five native records and cleanup](chat-probes/2026-09-14/task-6-binding/README.md#observed-association) show that both owned clients exited normally, the temporary active hook definition was removed, and the shared server and unrelated handler were preserved.

The next code checkpoint adds separate enrollment, participant and integration secrets in owned mode-0600 records, Linux boot/process-birth/executable checks, bounded native version helpers, and serialized persistence of the daemon-assigned incarnation. Native IDs locate records and never grant authority alone.
