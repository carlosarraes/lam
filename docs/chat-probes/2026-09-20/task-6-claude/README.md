On 2026-09-20, the local candidate was tested against Claude Code 2.1.273 in the private project `/tmp/lam-chat-task6-native.KlGYDF/claude-case-20260920/project`. The release binary SHA-256 was `6a55dd26cc28edb3780a1126bc5ec3a92f0c7481b83943535695fa2fcaa11010`; the scoped `--settings` hook file SHA-256 was `63ae1248b4280f54818c69ba17d2488a4aa502e3971d39a685f12799f7c657dc`. The Chat daemon used a private database and `--native-bindings`. No global Claude settings, permissions, or other sessions were changed.

The first SessionStart registered native session `7b017652-ff1f-4d9a-aee0-4e3be3d63142` but failed at the environment export. An owned, file-operation-only trace of a second startup showed `CLAUDE_ENV_FILE` pointing to a nonexistent `sessionstart-hook-1.sh`; append-only open returned `ENOENT`. The fix creates that file mode 0600 while still rejecting symlinks, non-owned files, non-private files, and invalid native IDs. A red/green regression test covers this exact missing-file case. The trace used only a scoped settings command and was removed from the active hook definition afterward.

After rebuilding, an owned print-mode session registered and ended with no new hook diagnostic. Its Bash request was denied by the ordinary noninteractive approval path; that denial was preserved. A separate owned interactive session then used normal folder trust and one-time Bash approval, not a permission override. Native session `0e9b86af-b16e-4c4f-9b0d-03b0b4a3145f` received a 0600 Claude environment file containing only `LAM_CHAT_CLAUDE_SESSION_ID` for that exact session. Its actual Bash tool invoked `lam inbox --json` and returned `events: []`. The native transcript records the exact successful tool result; the model reported zero entries. After normal `/exit`, the private database marked that exact session ended and ineligible. The private fixed-label diagnostic file remained at the two earlier output failures, with no new line from the corrected sessions.

This proves registration, environment propagation, native command authentication, and explicit SessionEnd for this Linux client build. It does **not** prove Claude peer delivery, refusal, busy/idle transitions, process restart, subagent isolation, the six directed client pairs, or a production installation. The test settings are opt-in to this owned case only.
