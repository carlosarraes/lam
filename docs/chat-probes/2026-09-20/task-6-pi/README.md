# Owned Pi bridge probe, 2026-09-20

The test used Pi 0.86.1 with `--no-extensions --extension integrations/pi/lam-chat.ts`, the isolated Chat store and daemon in `/tmp/lam-chat-task6-native.KlGYDF/claude-case-20260920`, and an owned Claude 2.1.278 sender. No shared Pi extension, Claude hook, daemon, or permission default was installed or changed. Both client sessions were created solely for this probe.

Pi 0.86.1 rewrites its OS process title to `pi`, so its script path disappears from `/proc/<pid>/cmdline`. The initial native enrollment failed closed. The extension now supplies its canonical own entrypoint to child commands; LAM checks its version and binds the exact Pi process lifetime. A real Pi session registered as `pi-01a0c005`, and a native Pi Bash call to the candidate binary's `inbox --json` authenticated and returned an empty inbox. The globally installed `lam` binary was older and lacked `inbox`, so the test explicitly invoked the candidate binary; this is a rollout item, not a binding failure.

The Pi extension starts one child bridge after successful enrollment. It subscribes to the private, participant-scoped event stream and writes nothing for an empty feed. On a directed arrival, the bridge claims one bounded batch through the Store owner, writes it to the extension, and waits briefly for an exact-attempt acknowledgement after `pi.sendMessage({ customType: "lam-chat-peer" }, { deliverAs: "steer", triggerTurn: true })` returns. A lost or invalid acknowledgement stays **Unknown**; the bridge does not replay it. Accepted means native queuing, not model reading or agreement.

The first owned Claude→Pi send exposed a bridge writer mismatch: Node supplied a Unix socket for child stdout, whereas the Codex hook writer accepts only FIFOs. The attempt became Unknown and was not replayed. A socketpair regression and a bridge-specific nonblocking writer fixed it. The second send, `CLAUDE_TO_PI_IDLE_SOCKETFIX`, reached idle Pi session `01a0c010-2b21-7715-83ef-6781e65456b4`; LAM recorded Accepted, Pi persisted a `lam-chat-peer` custom message with the fixed untrusted-data wrapper and full token, and the idle model started a turn.

For the busy case, the same Pi session called foreground Bash `sleep 25` at 18:26:48.383 UTC and completed normally at 18:27:13.394. LAM recorded Accepted for `CLAUDE_TO_PI_BUSY_SOCKETFIX` at 18:26:56.453, inside the active tool interval. Pi appended the custom message at 18:27:13.395, then its 18:27:15.702 final included the exact token. No tool or model was interrupted, cancelled, or backgrounded. This proves one idle and one busy directed pair; it does not prove every race, refusal, model behavior, Mac compatibility, or the remaining directed pairs.

The extension has not been installed globally. Pi's generic custom-message origin and the fixed wrapper remain the provenance available to the model; they are not a privileged system/developer role. The isolated transcripts and store retain test details, while this committed note contains no binding credentials or private message bodies beyond test nonces.
